# 0003: M2 and M3 scope without the VPS runner

Date: 2026-10-19 · Status: accepted

## Context

The maintainer asked to continue with M2 (agent MVP) and M3 (shareable + consumer skills), and
earlier said not to worry about the VPS agent. The repo has no git remote, so GitHub Actions, PRs
and npm publishing cannot run yet.

## Decision

Build everything that lives in the repository and can be tested locally; leave the runtime that
needs external services.

| In scope | Out of scope (for now) |
| --- | --- |
| API surface reports, token reports, computed version bump, changeset check | VPS runner, webhook listener, polling loop |
| Size budgets, visual regression baselines | Running GitHub Actions (no remote) |
| CI and release workflows, issue and PR templates (ready for a remote) | npm publishing |
| Maintainer agent plugin: skills, subagents, hooks, `config.yaml` with validation | Jira adapter (needs a Jira instance) |
| shadcn registry, `llms.txt`, `llms-full.txt`, `install.md` | Live model runs of the skill eval |
| Consumer skills, MCP server, skill-eval harness and scorer | |

## Defaults chosen

| Question | Default | Why |
| --- | --- | --- |
| API Extractor or own report? | Own report built on the TypeScript 6 compiler API. | API Extractor needs emitted `.d.ts` files and bundles TypeScript 5; packages here ship source. The report only needs exported names and signatures to classify changes. |
| Where do generated agent docs live? | `apps/site/public/` (`llms.txt`, `r/*.json`), regenerated by script, with drift tests. | The site is the public surface, so the files are served alongside it. |
| Visual baselines | Committed per platform by Vitest's screenshot matcher; macOS baselines now, Linux ones created by CI on first run. | Font rendering differs by OS. |
