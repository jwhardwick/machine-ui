# M1: Theme Engine + Live Storybook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A seed → contrast-safe token set engine, applied live via CSS variables, demonstrated in a Storybook with a live theme-editor addon, a theme-matrix story, five reference themes, and a public playground page.

**Architecture:** `@machine-ui/tokens` owns the schema (seed + token names), reference seeds, curated type pairs and the static `@theme inline` CSS. `@machine-ui/theme-engine` (pure TS, culori for colour maths) expands a seed into light/dark token sets, solving each required pair for WCAG contrast, and serialises them to CSS; only `applyTheme` touches the DOM. `@machine-ui/ui` wraps shadcn-style Radix components using Tailwind utilities that resolve to the engine's variables. Storybook and the site consume the packages from source.

**Tech Stack:** pnpm 11 workspaces, TypeScript 6.0 (strict; typescript-eslint does not support TS 7 yet), React 19.3, Tailwind 4.3 (`@tailwindcss/vite`), Vite 8, Vitest 5 (browser mode via Playwright for Storybook), Storybook 10.6 (react-vite, addon-vitest, addon-a11y), radix-ui 1.8, cva, tailwind-merge 3, culori 4, ESLint 10 flat config, Changesets 3.

**Spec:** `docs/SPEC.md` (M1 section + "Theme engine"). Project rules: `CLAUDE.md`.

## Global Constraints

- Package scope `@machine-ui/*`. Packages export TS source (`"exports": {".": "./src/index.ts"}`); build/publish is M2+.
- Tokens only in `packages/ui`: no raw colours, px values or font names. Enforced by `machine-ui/tokens-only`; never disabled.
- Engine writes plain semantic CSS variables. `packages/tokens/theme.css` maps them with `@theme inline` and contains only `var(--…)` values (plus `initial` resets).
- Engine variable names must not collide with Tailwind namespaces they map into: `--type-*` → `--text-*`, `--corner-*` → `--radius-*`, `--typeface-*` → `--font-*`, `--elevation-*` → `--shadow-*`, `--space-unit` → `--spacing`. Colour roles keep shadcn names (`--primary` → `--color-primary`). `--radius` is also emitted for shadcn compatibility.
- Colour generated in OKLCH. 11-step scales (50,100,…,900,950), sRGB gamut clamped.
- WCAG 2.2: 4.5:1 for text pairs, 3:1 for UI boundaries. Solved, not checked after. APCA Lc reported as advisory.
- Light and dark from the same seed. Every reference theme passes every pair in both.
- `theme-engine` imports nothing from React or the DOM outside `src/apply.ts`.
- No reference theme uses Inter, gradients, or maximum radius (seed `radius` < 1).
- Motion tokens collapse to `0ms` under `prefers-reduced-motion: reduce`.
- `pnpm check` = typecheck, lint, test, test:storybook, site build. Must pass before a task is done.

## Review Focus

1. **Extreme seeds** (hue 0 vs 360, max chroma at hue ~100 where sRGB is tight, chroma 0) must still produce passing pairs → Task 4 sweep test.
2. **Malformed share URLs** (garbage, missing keys, out-of-range numbers, unknown type pair) → `parseSeed` clamps or returns `null`, never throws → Task 6.
3. **Slider drag calls `applyTheme` many times** → one `<style>` per scope, reused; `dispose()` removes it; scoped themes don't bleed → Task 6.
4. **Web fonts fail to load** → every `--typeface-*` value ends in a generic family → Task 2.
5. **Reduced motion** → durations are `0ms` under the media query regardless of seed → Task 6.

### Task 3: Engine colour core

**Files:**
- Create: `packages/theme-engine/src/color/{oklch.ts,contrast.ts,scale.ts,solve.ts}`
- Test: `packages/theme-engine/src/color/color.test.ts`

**Interfaces — Produces:**
```ts
interface Oklch { l: number; c: number; h: number }
toGamut(c: Oklch): Oklch                    // sRGB-clamped, preserves l and h, reduces c (culori clampChroma)
formatOklch(c: Oklch): string               // "oklch(0.623 0.142 28.4)", 3dp/1dp
luminance(c: Oklch): number                 // WCAG relative luminance
wcagContrast(a: Oklch, b: Oklch): number
apcaContrast(text: Oklch, bg: Oklch): number // APCA-W3 0.1.9 Lc, signed
const SCALE_STEPS = [50,100,200,300,400,500,600,700,800,900,950] as const;
generateScale(hue: number, chroma: number): Record<ScaleStep, Oklch>
solveContrast(fg: Oklch, bg: Oklch, target: number): { fg: Oklch; bg: Oklch }
```
Scale: fixed lightness ladder `[0.97,0.93,0.87,0.78,0.68,0.58,0.49,0.41,0.33,0.25,0.18]`; chroma = `maxChroma * curve(step)` with a bell curve peaking at 500, `maxChroma = 0.02 + chroma * 0.2`, then `toGamut`. Neutral scales come from the same function with tiny chroma (Task 4).

Solve algorithm: keep `bg` fixed; pick the direction (toward L=0 or L=1) whose extreme gives the larger contrast; bisect `fg.l` between its current value and that extreme (20 iterations), re-clamping gamut each probe, returning the smallest move that meets `target + 0.05` margin. If the extreme can't reach the target, move `bg.l` away from fg the same way and retry. Throw `ContrastUnsolvableError` only if both fail.

Motion: none → `0ms` all; subtle → 100/150/200ms, standard `cubic-bezier(0.2,0,0,1)`; expressive → 150/250/400ms, emphasized `cubic-bezier(0.3,1.4,0.5,1)`.
