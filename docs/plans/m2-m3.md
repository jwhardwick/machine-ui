# M2 + M3 (repo-side) plan

Scope: decision 0003. Same rules as `CLAUDE.md`; `pnpm check` green before each commit.

## M2: maintenance pipeline

- [x] **1. API report.** `tooling/release/api-report.ts` lists every export of each package with its type signature into `api/<package>.api.md`. Drift test fails when source changes without regenerating.
- [x] **2. Token report.** `api/tokens.json`: colour roles, shared and mode tokens, type pair ids and presets.
- [x] **3. Version bump.** `pnpm release:bump [--base <ref>]` diffs both reports against the base, classifies each change (major / minor / patch per the spec's table) and prints `version: minor (2 new exports)`. `--check-changeset` fails if the changesets don't cover the computed level. Fixture tests for every rule.
- [x] **4. Size budgets.** size-limit with esbuild: per-component tree-shaken imports from `@machine-ui/ui` and the engine, with budgets.
- [ ] **5. Visual regression.** Screenshot tests of the theme matrix and screens across presets, light and dark.
- [ ] **6. CI and templates.** `.github/workflows/ci.yml`, `release.yml`, issue templates requiring acceptance criteria, PR template. Validated by test.
- [ ] **7. Maintainer plugin.** `agent/`: plugin manifest, seven maintainer skills (each ends with a verification step), subagents, hooks (block pushes to main and CI-config edits; lint after edits), `config.yaml` with schema validation.

## M3: shareable

- [ ] **8. shadcn registry.** Build `apps/site/public/r/*.json` from `packages/ui` (imports rewritten to shadcn aliases) plus one theme item per preset; validate against shadcn's schema; install into a fixture app and typecheck it.
- [ ] **9. Agent docs.** `llms.txt`, `llms-full.txt`, `install.md` generated from the registry and source, with drift tests.
- [ ] **10. Consumer skills.** `use-ds-install`, `use-ds-theme`, `use-ds-compose`, `use-ds-migrate`.
- [ ] **11. MCP server.** `@machine-ui/mcp`: `list_components`, `get_component`, `get_tokens`, `generate_theme`, tested through an in-memory client.
- [ ] **12. Skill eval harness.** Task definitions and a scorer that counts off-system styling; documented how to run against a model.
- [ ] **13. Wrap-up.** Docs, changeset, `CLAUDE.md` milestone, `pnpm check`.
